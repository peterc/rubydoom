Walk-trigger direction sensitivity
----------------------------------

Vanilla DOOM fires some walk-triggers only when crossed front→back
(the player approaches from the side of the front sidedef).
`Clipper#emit_crossings` currently fires on any cross. For E1M1 this
is fine — its W1 type-36 trigger and WR type-88 trigger both want
to fire either way. Add a per-special direction flag if a future
map depends on it.

Z-axis / vertical physics
-------------------------

Player is glued to `floor_at(x, y)`. No falling, no jumping. Lifts
work because the player's apparent height equals the sector's
current floor, which moves with the lift. This breaks if:
  * Player jumps off a ledge — they'd just teleport down to the
    new floor instantly (currently happens silently).
  * Lift comes up under a player who walked off it — collision
    against the rising ceiling not modeled.

For E1M1 traversal this is fine; for combat / falling / rocket
jumps later, needs real z.


Renderer at sub-radius wall proximity
-------------------------------------

If the camera ends up within `PLAYER_RADIUS` (16) of a wall
surface — normally impossible since collision uses a BB-straddle
rule that blocks corners and squeeze-through cases that the older
center-side check missed, but still reachable via the RUBYDOOM_X /
RUBYDOOM_Y env-var debug spawn — close segs project off-screen
(`sy_front_ceil` goes hugely negative because the ceiling is far
above the eye relative to the tiny z), so the renderer doesn't
emit ceiling visplane spans for those columns. The upper-half sky
pre-fill masks the gap as "looking up at sky" instead of as a HOM
hole. Real fix would be to either:

  * Clamp the rendering camera to be at least PLAYER_RADIUS from
    every wall surface (pure-renderer guard, doesn't affect physics).
  * Sweep accumulated visplane spans to fill any column whose top
    isn't actually covered by a wall, using the camera's own sector.

Neither is needed in normal play — only matters when debugging with
env-var spawn into impossible positions.
